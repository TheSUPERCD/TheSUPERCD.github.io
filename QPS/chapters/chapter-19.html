3. Foundations: Computing Realities, Linear Algebra & PDEs (Chapters 01–03)

3.1 Chapter 01: HPC Foundations, Arithmetic Intensity & The Roofline Model

💡 Plain-English Intuition: The Roofline Model

Imagine a sports car with an engine capable of 300 km/h ($P_{\text{peak}}$), but it only has a tiny fuel line ($BW_{\text{peak}}$). If the car burns 5 liters of fuel per kilometer (low arithmetic intensity $I$, e.g., vector addition or SpMV), the engine will choke because fuel cannot flow fast enough—the car is memory-bandwidth bound. If instead it requires almost no fuel to produce speed (high $I$, e.g., dense matrix multiplication $C = AB$), it accelerates all the way to its mechanical maximum speed—the car is compute-bound.

🔍 Roofline Formulation & Decryption

The attainable performance $P$ (in GFLOPS) on any hardware architecture is strictly bounded by:

$$P = \min\left( P_{\text{peak}}, \; I \times BW_{\text{peak}} \right)$$
  • $P_{\text{peak}}$: Theoretical peak floating-point rate $= \text{Sockets} \times \frac{\text{Cores}}{\text{Socket}} \times f_{\text{clock}} \times \frac{\text{FLOPs}}{\text{Cycle}}$.
  • $BW_{\text{peak}}$: Peak memory bandwidth between DRAM and CPU cache (in GB/s).
  • $I = \frac{\text{Total FLOPs}}{\text{Total Bytes Transferred}}$: Operational / Arithmetic Intensity.
  • $I^* = \frac{P_{\text{peak}}}{BW_{\text{peak}}}$: The "Machine Balance" / Knee of the curve.
    • If $I < I^*$: Code is Memory-Bound. Upgrading the CPU does nothing; only faster RAM helps!
    • If $I > I^*$: Code is Compute-Bound. Running at full hardware floating-point capacity!

✍️ Exam Hand-Calculation: Determining Memory vs Compute Bound

Problem: A dual-socket server has 16 cores per socket running at 2.5 GHz. Each core executes 16 FLOPs/cycle (AVX-512 FMA). Peak DRAM bandwidth is 100 GB/s. A sparse matrix-vector multiply (SpMV) performs $2 N_{nz}$ FLOPs and transfers $12$ bytes per non-zero from memory. Is this kernel memory-bound or compute-bound, and what is its maximum attainable performance?

  1. Calculate $P_{\text{peak}}$: $$P_{\text{peak}} = 2 \times 16 \times 2.5 \times 10^9 \times 16 = 1.28 \times 10^{12} \text{ FLOP/s} = 1280 \text{ GFLOPS}$$
  2. Calculate Machine Balance $I^*$: $$I^* = \frac{P_{\text{peak}}}{BW_{\text{peak}}} = \frac{1280 \text{ GFLOPS}}{100 \text{ GB/s}} = 12.8 \text{ FLOPs/byte}$$
  3. Calculate Kernel Arithmetic Intensity $I$: $$I = \frac{2 \text{ FLOPs}}{12 \text{ bytes}} = \frac{1}{6} \approx 0.167 \text{ FLOPs/byte}$$
  4. Classify & Compute Attainable Performance: Since $I = 0.167 \ll 12.8 = I^*$, the SpMV kernel is strictly memory-bound! $$P = I \times BW_{\text{peak}} = 0.167 \times 100 \text{ GB/s} = 16.7 \text{ GFLOPS}$$ Notice: The processor operates at only $\frac{16.7}{1280} \approx 1.3\%$ of its peak capacity! $98.7\%$ of the execution time is spent idling, waiting for DRAM.

⚠️ Deadly Exam Trap: Truncation Error vs Round-Off Error

• Truncation Error: Caused by mathematical discretization (e.g. chopping a Taylor series off at $O(h^2)$). It shrinks as $h \to 0$.
• Round-off Error: Caused by finite computer representation (IEEE 754 float). It grows as $h \to 0$ because subtracting nearly identical floating-point numbers causes catastrophic cancellation! The total error curve is a "V-shape" with an optimal step size $h^*$.

3.2 Chapter 02: The Four Fundamental Subspaces & Solvability

💡 Plain-English Intuition: Strang's Big Picture

Think of an $m \times n$ matrix $A$ as an information pipeline from an $n$-dimensional room ($\mathbb{R}^n$) to an $m$-dimensional room ($\mathbb{R}^m$).
In the input room, vectors in the Row Space $\mathcal{R}(A^T)$ survive and produce distinct output vectors in the Column Space $\mathcal{R}(A)$. Vectors in the Nullspace $\mathcal{N}(A)$ are sucked into a black hole ($Ax = 0$) and permanently destroyed. The Row Space and Nullspace are perpendicular complements—together they make up the entire input room ($\mathbb{R}^n$).

🔍 Fundamental Theorem of Linear Algebra (Strang)

For any real matrix $A \in \mathbb{R}^{m \times n}$ with rank $r$:

$$\mathcal{R}(A^T) \perp \mathcal{N}(A) \quad \text{and} \quad \mathcal{R}(A^T) \oplus \mathcal{N}(A) = \mathbb{R}^n$$ $$\mathcal{R}(A) \perp \mathcal{N}(A^T) \quad \text{and} \quad \mathcal{R}(A) \oplus \mathcal{N}(A^T) = \mathbb{R}^m$$

Fredholm Alternative for Solvability:

$$Ax = b \text{ has a solution} \iff b \in \mathcal{R}(A) \iff b \perp \mathcal{N}(A^T) \iff y^T b = 0 \text{ for all } y \in \mathcal{N}(A^T)$$

Uniqueness: If a solution exists, it is unique if and only if $\mathcal{N}(A) = \{0\}$ (full column rank $r = n$). If $\mathcal{N}(A) \ne \{0\}$, the general solution is $x = x_p + x_h$, where $x_p$ is any particular solution and $x_h \in \mathcal{N}(A)$.

⚠️ Deadly Exam Trap: Small Determinant $\ne$ Ill-Conditioned!

A common exam trick asks: "If $\det(A) = 10^{-100}$, is $A$ ill-conditioned?"
NO! Consider $A = 0.1 \times I_{100}$. Its determinant is $(0.1)^{100} = 10^{-100}$, but its condition number is $\kappa_2(A) = \frac{0.1}{0.1} = 1.0$ (perfectly conditioned!). Determinants measure volume scaling, not relative error sensitivity. Never use determinant to judge conditioning.

3.3 Chapter 03: PDE Discretization (FDM/FEM) & Sparse Storage Schemes

💡 Plain-English Intuition: 5-Point Laplacian Stencil

The 2D Poisson equation $-\nabla^2 u = f$ describes steady-state physical diffusion (heat, electrostatics). In discrete space, the Laplacian at a point $(i, j)$ is simply the difference between the point's value and the average of its four immediate neighbors (North, South, East, West). When we write this balance for every grid point, we get a matrix $A$ where each row has at most 5 non-zero entries, regardless of how large the matrix is!

🔍 5-Point Stencil Equation

$$\frac{4u_{i,j} - u_{i+1,j} - u_{i-1,j} - u_{i,j+1} - u_{i,j-1}}{h^2} = f_{i,j} + O(h^2)$$

For an $N \times N$ interior grid ($n = N^2$ unknowns), the matrix $A$ is block-tridiagonal:

$$A = \frac{1}{h^2} \begin{bmatrix} T & -I & & \\ -I & T & -I & \\ & \ddots & \ddots & \ddots \\ & & -I & T \end{bmatrix}, \quad T = \begin{bmatrix} 4 & -1 & & \\ -1 & 4 & -1 & \\ & \ddots & \ddots & \ddots \\ & & -1 & 4 \end{bmatrix}$$

✍️ Exam Hand-Calculation: Building CSR, CSC, and COO Arrays

Problem: Given the $4 \times 4$ sparse matrix $A$ with $N_{nz} = 7$ non-zeros:

$$A = \begin{bmatrix} 10 & 0 & 2 & 0 \\ 0 & 20 & 0 & 0 \\ 3 & 0 & 30 & 4 \\ 0 & 0 & 0 & 40 \end{bmatrix}$$

Write out the canonical sparse storage arrays by hand (using 0-based indexing):

  1. CSR (Compressed Sparse Row):
    • `values`: Scan row-by-row $\to$ [10, 2, 20, 3, 30, 4, 40] (size $N_{nz} = 7$)
    • `col_ind`: Column index for each non-zero in `values`: [0, 2, 1, 0, 2, 3, 3] (size $N_{nz} = 7$)
    • `row_ptr`: Where each row starts in `values`, plus the sentinel element $N_{nz}$ at the end:
      Row 0 starts at index 0 (has 2 elements)
      Row 1 starts at index 2 (has 1 element)
      Row 2 starts at index 3 (has 3 elements)
      Row 3 starts at index 6 (has 1 element)
      Sentinel index at end = 7
      `row_ptr` = [0, 2, 3, 6, 7] (size $n+1 = 5$)
  2. CSC (Compressed Sparse Column):
    • Scan column-by-column: Col 0: $(0,0)=10, (2,0)=3$. Col 1: $(1,1)=20$. Col 2: $(0,2)=2, (2,2)=30$. Col 3: $(2,3)=4, (3,3)=40$.
    • `values` = [10, 3, 20, 2, 30, 4, 40]
    • `row_ind` = [0, 2, 1, 0, 2, 2, 3]
    • `col_ptr` = [0, 2, 3, 5, 7]
  3. COO (Coordinate Format):
    • Three parallel arrays of length $N_{nz} = 7$:
      `row` = [0, 0, 1, 2, 2, 2, 3]
      `col` = [0, 2, 1, 0, 2, 3, 3]
      `val` = [10, 2, 20, 3, 30, 4, 40]
  4. DIA (Diagonal Format) & ELLPACK:
    • DIA: Stores diagonals in a 2D array with an `offsets` array. Ideal when nonzeros lie strictly on a few continuous diagonals (e.g. 5-point stencil has offsets $[-N, -1, 0, 1, N]$).
    • ELLPACK: Padds all rows to fixed width $K = \max_i (\text{nz}_i)$ with zeros. Perfect for SIMD/GPU vectorization because memory reads are coalesced and branch-free!

4. Solvers I: Direct Solvers, Factorizations & Classical Iterations (Chapters 04–05)

4.1 Chapter 04: Gaussian Elimination, LU, Cholesky, Fill-in & TDMA

💡 Plain-English Intuition: The Fill-In Curse

In 1D, nodes only talk to left and right neighbors. Gaussian elimination preserves tridiagonal sparsity, solving in $O(n)$ time. But in 2D and 3D, nodes talk across grid rows. When you eliminate node 1, it creates artificial connections (fill-in) between all its neighbors. By the time elimination finishes, your sparse matrix has filled with dense blocks—memory requirements skyrocket from $O(n)$ to $O(n^{1.5})$ in 2D and $O(n^{5/3})$ in 3D, while runtime explodes to $O(n^2)$ and $O(n^{7/3})$. This is why direct solvers fail on large PDE problems!

Problem: Solve the tridiagonal system $A x = d$ for $n=3$:

$$\begin{bmatrix} 2 & -1 & 0 \\ -1 & 2 & -1 \\ 0 & -1 & 2 \end{bmatrix} \begin{bmatrix} x_1 \\ x_2 \\ x_3 \end{bmatrix} = \begin{bmatrix} 1 \\ 0 \\ 1 \end{bmatrix}$$

Let subdiagonal be $a = [-1, -1]$, main diagonal $b = [2, 2, 2]$, superdiagonal $c = [-1, -1]$, and RHS $d = [1, 0, 1]$.

  1. Forward Elimination Sweep (modify $b_i$ and $d_i$):
    • $i = 1$: $b_1' = b_1 = 2$, $d_1' = d_1 = 1$.
    • $i = 2$: Multiplier $m_2 = \frac{a_2}{b_1'} = \frac{-1}{2} = -0.5$.
      $b_2' = b_2 - m_2 c_1 = 2 - (-0.5)(-1) = 2 - 0.5 = 1.5$.
      $d_2' = d_2 - m_2 d_1' = 0 - (-0.5)(1) = 0.5$.
    • $i = 3$: Multiplier $m_3 = \frac{a_3}{b_2'} = \frac{-1}{1.5} = -\frac{2}{3}$.
      $b_3' = b_3 - m_3 c_2 = 2 - \left(-\frac{2}{3}\right)(-1) = 2 - \frac{2}{3} = \frac{4}{3} \approx 1.333$.
      $d_3' = d_3 - m_3 d_2' = 1 - \left(-\frac{2}{3}\right)(0.5) = 1 + \frac{1}{3} = \frac{4}{3}$.
  2. Backward Substitution Sweep:
    • $x_3 = \frac{d_3'}{b_3'} = \frac{4/3}{4/3} = 1$.
    • $x_2 = \frac{d_2' - c_2 x_3}{b_2'} = \frac{0.5 - (-1)(1)}{1.5} = \frac{0.5 + 1}{1.5} = \frac{1.5}{1.5} = 1$.

4.2 Chapter 05: Classical Iterative Solvers (Jacobi, Gauss-Seidel, SOR) & Spectral Convergence

💡 Plain-English Intuition: Jacobi vs Gauss-Seidel vs SOR

• Jacobi is cautious: Everyone computes their new values at the same time using only the yesterday's values ($x^{(k)}$). It can be executed completely in parallel, but it is slow.
• Gauss-Seidel is eager: As soon as person 1 computes their updated value ($x_1^{(k+1)}$), person 2 immediately uses it! Using the newest information cuts the error twice as fast, but introduces sequential data dependencies.
• SOR is bold: Gauss-Seidel points in the right direction. SOR says: "Don't just walk to the Gauss-Seidel point; overshoot it by a factor $\omega > 1$!" By extrapolating, it speeds up convergence by an entire order of magnitude!

🔍 Splitting Decomposition: $A = D - L - U$

⚠️ Deadly Exam Trap: The Optimal $\omega$ Formula for SOR

Professors frequently ask you to calculate the optimal $\omega$ for SOR given $\rho(G_J)$ on an exam: $$\omega_{\text{opt}} = \frac{2}{1 + \sqrt{1 - \rho(G_J)^2}}$$ Key Theorems to Quote:
1. Kahan's Theorem: $\rho(G_{SOR}) \ge |\omega - 1|$. Therefore, SOR converges only if $0 < \omega < 2$. If $\omega \ge 2$, it is guaranteed to diverge!
2. Ostrowski-Reich Theorem: If $A$ is SPD and $0 < \omega < 2$, SOR is guaranteed to converge for any initial guess $x_0$.
3. Poisson 2D Iteration Count: Jacobi requires $O(N^2)$ iterations; Gauss-Seidel requires $O(N^2)$ iterations ($\approx$ half of Jacobi); optimal SOR drops this to $O(N)$ iterations!

5. Solvers II: Spectral Theory, Condition Numbers & Orthogonalization (Chapters 06–07)

5.1 Chapter 06: Eigenvalues, SVD, Rayleigh Quotient & Matrix Conditioning

💡 Plain-English Intuition: Eigenvalues vs Singular Values

• Eigenvalues ($Ax = \lambda x$): Act on a single space ($\mathbb{R}^n \to \mathbb{R}^n$). They tell you which special directions $x$ are purely stretched or shrunk by factor $\lambda$ without rotating.
• Singular Values ($A = U \Sigma V^T$): Act between two possibly different spaces ($\mathbb{R}^n \to \mathbb{R}^m$). If you feed the unit sphere into matrix $A$, the output is a tilted hyper-ellipsoid. The lengths of the principal semi-axes are the singular values $\sigma_1 \ge \sigma_2 \ge \dots \ge \sigma_r > 0$!

🔍 Condition Number & Perturbation Error Bounds

The 2-norm condition number of matrix $A$ is defined as:

$$\kappa_2(A) = \|A\|_2 \|A^{-1}\|_2 = \frac{\sigma_{\max}(A)}{\sigma_{\min}(A)} \ge 1$$

If $A$ is real symmetric positive definite (SPD), singular values equal eigenvalues: $\kappa_2(A) = \frac{\lambda_{\max}}{\lambda_{\min}}$.

The Fundamental Perturbation Inequality:

$$\frac{\|\delta x\|}{\|x\|} \le \kappa(A) \left( \frac{\|\delta A\|}{\|A\|} + \frac{\|\delta b\|}{\|b\|} \right)$$

Rule of Thumb: If $\kappa(A) \approx 10^k$, you lose up to $k$ decimal digits of precision in the computed solution. In IEEE 754 double precision (which has 16 digits), if $\kappa(A) \ge 10^{16}$, the computed solution is pure numerical garbage!

⚠️ Deadly Exam Trap: Rayleigh Quotient & Min-Max Theorem

The Rayleigh quotient is: $$R_A(x) = \frac{x^T A x}{x^T x}$$ Courant-Fischer Min-Max Theorem: For any real symmetric matrix $A$: $$\lambda_{\min} \le R_A(x) \le \lambda_{\max} \quad \text{for all } x \ne 0$$ The stationary points ($\nabla R_A(x) = 0$) are exactly the eigenvectors of $A$, with values equal to the corresponding eigenvalues!

5.2 Chapter 07: Gram-Schmidt (CGS vs MGS), QR Factorization & Householder/Givens

💡 Plain-English Intuition: Classical vs Modified Gram-Schmidt

• Classical Gram-Schmidt (CGS): You want to make vector $v_k$ perpendicular to all previous vectors $q_1, \dots, q_{k-1}$. In CGS, you compute all projections onto $q_j$ simultaneously from the original $a_k$. In floating-point arithmetic, rounding errors in early directions bleed into later directions, causing total loss of orthogonality (the computed $Q$ matrix fails $Q^T Q = I$!).
• Modified Gram-Schmidt (MGS): Instead of subtracting all projections at once, you project $a_k$ onto $q_1$, immediately subtract it, take the resulting intermediate vector and project it onto $q_2$, subtract it, and so forth. This sequential deflation prevents error accumulation and keeps $Q$ numerically orthogonal!

⚠️ Deadly Exam Trap: Why QR is Superior to Normal Equations for Least Squares

To solve $\min_x \|Ax - b\|_2$ for tall matrix $A \in \mathbb{R}^{m \times n}$ ($m > n$):
• Normal Equations: $A^T A x = A^T b$. Cost is cheap ($\frac{1}{2}mn^2 + \frac{1}{6}n^3$), BUT the condition number is squared: $$\kappa_2(A^T A) = [\kappa_2(A)]^2$$ If $\kappa_2(A) = 10^8$, $A^T A$ has $\kappa_2 = 10^{16}$—it becomes completely singular in double precision!
• QR Approach: $A = QR \implies R x = Q^T b$. Solved by back substitution. The condition number is strictly preserved: $\kappa_2(R) = \kappa_2(A)$. Never form $A^T A$ explicitly on an exam!

6. Solvers III: Projection, Steepest Descent & Conjugate Gradient (Chapters 08–10)

6.1 Chapter 08: Petrov-Galerkin Projections & Method of Steepest Descent

💡 Plain-English Intuition: The Petrov-Galerkin Framework

Suppose solving $Ax = b$ in full space $\mathbb{R}^n$ is too expensive ($n = 10^7$). We choose a small $m$-dimensional playground called the Search Subspace $K$ ($m \ll n$) and look for an approximate solution $\tilde{x} = x_0 + \delta$ with $\delta \in K$.
To select the best candidate in $K$, we pick a Constraint Subspace $L$ and demand that the residual $r = b - A\tilde{x}$ must be completely blind (perpendicular) to $L$: $r \perp L$.
• If $L = K$: Galerkin condition (orthogonal projection).
• If $L = AK$: Minimal Residual condition (minimizes Euclidean norm of residual $\|r\|_2$).

🔍 Quadratic Functional & Steepest Descent

For symmetric positive definite (SPD) matrix $A$, solving $Ax = b$ is mathematically identical to finding the minimum of the parabolic bowl:

$$\phi(x) = \frac{1}{2} x^T A x - b^T x$$

The gradient of $\phi(x)$ is $\nabla \phi(x) = Ax - b = -r$. Therefore, the direction of steepest descent is the residual $r$!

Steepest Descent Algorithm:

$$\alpha_k = \frac{r_k^T r_k}{r_k^T A r_k}, \quad x_{k+1} = x_k + \alpha_k r_k, \quad r_{k+1} = r_k - \alpha_k A r_k$$

The Orthogonality Trap: $r_{k+1}^T r_k = 0$. Each step is strictly perpendicular to the previous step! In an elongated elliptical canyon ($\kappa(A) \gg 1$), this forces the algorithm into an agonizing 90-degree zig-zag across the canyon walls, crawling forward like a snail.

Convergence Bound:

$$\|e_{k+1}\|_A \le \left( \frac{\kappa - 1}{\kappa + 1} \right) \|e_k\|_A$$

6.2 Chapter 09: Krylov Subspaces, Arnoldi, FOM & Symmetric Lanczos

💡 Plain-English Intuition: Krylov Subspace $\mathcal{K}_m(A, r_0)$

What is the natural space to look for the solution to $Ax = b$? Start with initial residual $r_0$. Apply matrix $A$ to see how the system responds: $A r_0$. Apply it again: $A^2 r_0$. The space spanned by these vectors, $\mathcal{K}_m(A, r_0) = \text{span}\{r_0, Ar_0, \dots, A^{m-1}r_0\}$, contains all degree-$(m-1)$ matrix polynomials acting on $r_0$. By the Cayley-Hamilton theorem, $A^{-1}$ can be expressed as a polynomial in $A$; therefore, the exact solution $x^*$ is guaranteed to lie in a high-enough dimensional Krylov space!

🔍 Arnoldi Relation & Lanczos Tridiagonal Collapse

Arnoldi's algorithm applies Modified Gram-Schmidt to the Krylov vectors, yielding:

$$A V_m = V_m H_m + h_{m+1, m} v_{m+1} e_m^T = V_{m+1} \tilde{H}_m$$
  • $V_m \in \mathbb{R}^{n \times m}$ has orthonormal columns: $V_m^T V_m = I_m$.
  • $H_m = V_m^T A V_m$ is an $m \times m$ upper Hessenberg matrix ($h_{ij} = 0$ for $i > j+1$).

The Symmetric Miracle (Lanczos): If $A$ is symmetric ($A = A^T$), then:

$$H_m = V_m^T A V_m = (V_m^T A V_m)^T = H_m^T$$

A matrix that is both upper Hessenberg and symmetric must be TRIDIAGONAL ($H_m = T_m$)! The long orthogonalization loop collapses into a 3-term recurrence:

$$\beta_{j+1} v_{j+1} = A v_j - \alpha_j v_j - \beta_j v_{j-1}$$

Significance: You only need to store 3 vectors in memory instead of all $m$ vectors!

6.3 Chapter 10: Conjugate Gradient (CG) Method – The Master Synthesis

💡 Plain-English Intuition: Why CG Destroys Steepest Descent

Steepest Descent zigzags because orthogonal steps ($p_{k+1} \perp p_k$) in an elliptical bowl undo progress made in previous directions. The Conjugate Gradient method fixes this by choosing directions that are $A$-orthogonal (conjugate): $p_i^T A p_j = 0$.
Geometrically, $A$-orthogonality means orthogonal with respect to the elliptical contours! When you minimize along $p_k$ to the bottom of the 1D slice, your error $e_{k+1}$ is guaranteed to be $A$-orthogonal to $p_k$. You will never need to step in that direction again! In an $n$-dimensional space, CG finds the exact minimum in at most $n$ steps.

🔍 The Complete Conjugate Gradient Algorithm (Memorize for Exam!)

Given A (SPD), b, and initial guess x0:
r0 = b - A*x0
p0 = r0

For k = 0, 1, 2, ... until ||rk|| / ||r0|| < tol:
    w_k = A * p_k                      [1 SpMV]
    alpha_k = (rk^T * rk) / (pk^T * w_k)  [1 Dot Product]
    x_{k+1} = x_k + alpha_k * p_k       [1 AXPY]
    r_{k+1} = r_k - alpha_k * w_k       [1 AXPY]
    beta_k  = (r_{k+1}^T * r_{k+1}) / (rk^T * rk)  [1 Dot Product]
    p_{k+1} = r_{k+1} + beta_k * p_k    [1 AXPY]

Cost per step: Exactly 1 SpMV, 2 Inner Products, 3 AXPYs.

✍️ Exam Hand-Calculation: One Full Step of Conjugate Gradient

Problem: Solve $Ax = b$ starting from $x_0 = [0, 0]^T$ using CG:

$$A = \begin{bmatrix} 2 & -1 \\ -1 & 2 \end{bmatrix}, \quad b = \begin{bmatrix} 1 \\ 0 \end{bmatrix}$$
  1. Initialize:
    • $r_0 = b - A x_0 = [1, 0]^T - [0, 0]^T = [1, 0]^T$.
    • $p_0 = r_0 = [1, 0]^T$.
    • $r_0^T r_0 = (1)^2 + (0)^2 = 1.0$.
  2. Step 1: Compute $\alpha_0$ and update $x_1, r_1$:
    • $w_0 = A p_0 = \begin{bmatrix} 2 & -1 \\ -1 & 2 \end{bmatrix} \begin{bmatrix} 1 \\ 0 \end{bmatrix} = \begin{bmatrix} 2 \\ -1 \end{bmatrix}$.
    • $p_0^T w_0 = [1, 0] \begin{bmatrix} 2 \\ -1 \end{bmatrix} = 2$.
    • $\alpha_0 = \frac{r_0^T r_0}{p_0^T w_0} = \frac{1}{2} = 0.5$.
    • $x_1 = x_0 + \alpha_0 p_0 = \begin{bmatrix} 0 \\ 0 \end{bmatrix} + 0.5 \begin{bmatrix} 1 \\ 0 \end{bmatrix} = \begin{bmatrix} 0.5 \\ 0 \end{bmatrix}$.
    • $r_1 = r_0 - \alpha_0 w_0 = \begin{bmatrix} 1 \\ 0 \end{bmatrix} - 0.5 \begin{bmatrix} 2 \\ -1 \end{bmatrix} = \begin{bmatrix} 0 \\ 0.5 \end{bmatrix}$.
  3. Step 2: Compute $\beta_0$ and update search direction $p_1$:
    • $r_1^T r_1 = (0)^2 + (0.5)^2 = 0.25$.
    • $\beta_0 = \frac{r_1^T r_1}{r_0^T r_0} = \frac{0.25}{1.0} = 0.25$.
    • $p_1 = r_1 + \beta_0 p_0 = \begin{bmatrix} 0 \\ 0.5 \end{bmatrix} + 0.25 \begin{bmatrix} 1 \\ 0 \end{bmatrix} = \begin{bmatrix} 0.25 \\ 0.5 \end{bmatrix}$.
  4. Check $A$-Conjugacy: $$p_0^T A p_1 = [1, 0] \begin{bmatrix} 2 & -1 \\ -1 & 2 \end{bmatrix} \begin{bmatrix} 0.25 \\ 0.5 \end{bmatrix} = [2, -1] \begin{bmatrix} 0.25 \\ 0.5 \end{bmatrix} = 2(0.25) - 1(0.5) = 0.5 - 0.5 = 0!$$ Exactly zero! Hand calculation verified.

⚠️ Deadly Exam Trap: The CG Chebyshev Error Bound

The error bound of CG in the energy norm is governed by the square root of the condition number: $$\|e_k\|_A \le 2 \left( \frac{\sqrt{\kappa_2(A)} - 1}{\sqrt{\kappa_2(A)} + 1} \right)^k \|e_0\|_A$$ Comparison with Steepest Descent:
• Steepest Descent factor: $\frac{\kappa - 1}{\kappa + 1}$.
• Conjugate Gradient factor: $\frac{\sqrt{\kappa} - 1}{\sqrt{\kappa} + 1}$.
For $\kappa = 10,000$, $\sqrt{\kappa} = 100$. Steepest descent contraction factor is $\frac{9999}{10001} \approx 0.9998$ (takes $\approx 23,000$ iterations). CG contraction factor is $\frac{99}{101} \approx 0.980$ (takes $\approx 230$ iterations—100x faster!).

7. Solvers IV: Non-Symmetric Solvers & Preconditioning (Chapters 11–12)

7.1 Chapter 11: Non-Symmetric Krylov Solvers (GMRES, BiCG, CGS, BiCGSTAB)

💡 Plain-English Intuition: The Faber-Manteuffel Dilemma

In symmetric systems, Lanczos gave us both residual optimality and a cheap 3-term recurrence. But when $A \ne A^T$, the mathematical landscape fractures. The celebrated Faber-Manteuffel Theorem (1984) proved that for general non-symmetric matrices, you cannot have both!
You must make a choice:
• Choose Optimality (GMRES): Minimize the true residual $\|b - Ax\|_2$ at every single step, but pay the price of storing all past basis vectors ($O(m^2)$ memory and flops!).
• Choose Short Recurrences (BiCG / BiCGSTAB): Keep memory tiny and constant ($O(1)$ vectors stored), but sacrifice monotonic residual minimization.

⚠️ Deadly Exam Trap: How GMRES Solves Least Squares via Givens Rotations

GMRES projects $Ax = b$ to the $(m+1) \times m$ least squares problem: $$\min_{y \in \mathbb{R}^m} \| \beta e_1 - \tilde{H}_m y \|_2$$ where $\beta = \|r_0\|_2$ and $\tilde{H}_m$ is extended upper Hessenberg.
How is this solved in $O(m)$ flops?
At each step $j$, only one new subdiagonal entry $h_{j+1, j}$ exists! We apply a single $2 \times 2$ Givens rotation $G_j$ to eliminate $h_{j+1, j}$, transforming $\tilde{H}_m$ into upper triangular $R_m$. The residual norm at step $m$ is given for free as the absolute value of the last component of the transformed RHS vector, without forming $x_m$!

7.2 Chapter 12: Preconditioning Techniques

💡 Plain-English Intuition: Preconditioning

If your matrix $A$ has a condition number $\kappa = 10^6$, the energy surface is a violently squashed canyon. Steepest descent and CG bounce around because the walls are steep and the floor is flat. A preconditioner $M \approx A$ is an invertible coordinate transformation. Multiplying by $M^{-1}$ stretches the squashed ellipse back into a nearly perfect round bowl ($\kappa(M^{-1}A) \approx 1$). On a round bowl, the negative gradient points straight to the center—CG reaches the solution in just a few iterations!

🔍 The Three Classical Preconditioned Systems

System Form Mathematical Equation Impact on Residual & Symmetry
Left Preconditioning $M^{-1} A x = M^{-1} b$ The solver minimizes preconditioned residual $\|M^{-1} r\|_2$, not true residual $\|r\|_2$. Destroys symmetry even if $A$ and $M$ are symmetric!
Right Preconditioning $A M^{-1} y = b, \quad x = M^{-1} y$ Minimizes true residual $\|b - A x\|_2$! Preferred for GMRES because stopping criteria match original physical tolerance.
Split Preconditioning $L^{-1} A L^{-T} \tilde{x} = L^{-1} b, \quad M = L L^T$ Preserves symmetry! If $A$ and $M$ are SPD, the preconditioned matrix $L^{-1} A L^{-T}$ is strictly SPD, allowing standard Conjugate Gradient to run.

✍️ Exam Hand-Calculation: The PCG Algorithm Modifications

In Preconditioned Conjugate Gradient (PCG), we solve $M z_k = r_k$ in every iteration. The standard CG formulas change in exactly two places:

  1. Step Length $\alpha_k$: $$\alpha_k = \frac{r_k^T z_k}{p_k^T A p_k} \quad (\text{instead of } \frac{r_k^T r_k}{p_k^T A p_k})$$
  2. Momentum Scalar $\beta_k$: $$\beta_k = \frac{r_{k+1}^T z_{k+1}}{r_k^T z_k} \quad (\text{instead of } \frac{r_{k+1}^T r_{k+1}}{r_k^T r_k})$$
  3. Search Direction Update: $p_{k+1} = z_{k+1} + \beta_k p_k$ (use preconditioned residual $z_{k+1}$, not $r_{k+1}$!).

⚠️ Deadly Exam Trap: Preconditioner Selection Trade-Off

An ideal preconditioner must balance two opposing forces:
1. Effectiveness: $M^{-1}$ must be as close to $A^{-1}$ as possible (so $\kappa(M^{-1}A) \approx 1$).
2. Application Cost: Solving $M z = r$ must be computationally cheap ($O(n)$ flops).
• Jacobi (Diagonal) Preconditioner ($M = \text{diag}(A)$): Trivial to invert ($O(n)$ flops), but only fixes bad row scaling; does not change asymptotic condition number of PDE grids.
• Incomplete Cholesky / LU (IC(0) / ILU(0)): Computes $A \approx \tilde{L}\tilde{U}$ matching only the non-zero pattern of $A$ (zero fill-in). Applying $M^{-1}$ requires two triangular solves ($O(N_{nz})$ flops). Dramatically reduces iteration count!

8. Architecture & Memory: Hierarchy, Cache Locality & False Sharing (Chapter 13)

8.1 The Memory Wall & Cache Hierarchy

💡 Plain-English Intuition: The Latency Analogy

If an ALU cycle (0.5 ns) is scaled to 1 human second:
• L1 Cache (1 ns): 2 seconds (reaching for a pen on your desk).
• L2 Cache (4 ns): 8 seconds (grabbing a book from the shelf).
• L3 Cache (15 ns): 30 seconds (walking down the hallway to the file cabinet).
• Main Memory DRAM (80 ns): 2.7 minutes (walking across campus to the library!).
When your code has a cache miss, the supercomputer CPU does not compute—it sits paralyzed for hundreds of cycles waiting for the memory bus.

🔍 Cache Architecture & The 3 C's of Cache Misses

A cache line is universally 64 bytes (holds 8 double-precision floats). Cache organization is defined by $(S, E, B)$:

$$C = S \times E \times B$$
  • $B = 64$ bytes (Block size).
  • $E$: Number of lines per set (Associativity). Direct-mapped has $E=1$; $E$-way set associative has $E > 1$; fully associative has $S=1$.
  • $S$: Number of sets.

The 3 C's of Cache Misses (Hill & Smith):

  1. Compulsory (Cold) Miss: First time data is accessed. Cannot be avoided except by hardware prefetching.
  2. Capacity Miss: The active working set of your algorithm simply exceeds the total size $C$ of the cache.
  3. Conflict Miss: The cache has plenty of room, but multiple active memory addresses hash to the same cache set (common when array dimensions are powers of 2!).

✍️ Exam Hand-Calculation: Loop Tiling for Matrix Multiplication ($C = AB$)

Problem: Standard dense matrix multiplication $C = AB$ for $n \times n$ matrices has $2n^3$ flops. In the naive triple loop (`i-j-k`), column elements of $B$ are accessed with stride $n$, evicting previously loaded cache lines. How does cache tiling / blocking reduce DRAM traffic?

  1. Naive Loop Cache Misses: Assuming $n$ is large so a row does not fit in cache, every read of $B[k][j]$ causes a cache miss. Total cache misses $= O(n^3)$.
  2. Tiled / Blocked Loop: Divide matrices into sub-blocks of size $b \times b$. Choose tile size $b$ such that three tiles fit simultaneously into L1 cache: $$3 \times b^2 \times 8 \text{ bytes} \le C_{\text{L1}}$$ For each block multiplication $C_{tile} \mathrel{+}= A_{tile} B_{tile}$:
    • Data loaded per tile: $2 b^2$ floats $= 2 b^2 \times 8$ bytes.
    • FLOPs performed per tile: $2 b^3$ flops.
    • Number of block pairs: $(n/b)^3$.
  3. Total Tiled Cache Misses: $$\text{Total Misses} \approx \left(\frac{n}{b}\right)^3 \times \frac{2 b^2}{B/8} = O\left( \frac{n^3}{b} \right)$$ The Payoff: Cache misses are reduced by a factor of $b$! If tile size $b = 64$, DRAM traffic drops by 64x!

⚠️ Deadly Exam Trap: False Sharing in Multithreading

What is False Sharing?
Two threads running on separate CPU cores modify independent variables (e.g. `thread_sum[0]` and `thread_sum[1]`). The variables are completely logically unrelated.
Why does performance collapse?
Because `thread_sum[0]` and `thread_sum[1]` sit adjacent in memory on the SAME 64-byte cache line! Under the hardware MESI cache coherence protocol, when Core 0 writes to `thread_sum[0]`, it marks the entire 64-byte cache line in Core 1's cache as INVALID (I). When Core 1 tries to write to `thread_sum[1]`, it suffers a cache miss, loads the line from Core 0, and marks Core 0's line as INVALID. The line bounces back and forth across the interconnect ("ping-ponging"), destroying multithreaded performance!
Remediation: Pad variables to 64 bytes (`alignas(64) double thread_sum[MAX_THREADS][8];`) or accumulate in local thread registers.

✍️ Exam Hand-Calculation: Hockney's $\alpha$-$\beta$ Communication Cost Model

Point-to-point message transmission time between two processors is modeled by:

$$T_{\text{comm}} = \alpha + \beta L$$
  • $\alpha$ ($t_s$): Startup latency (fixed overhead to negotiate envelope, routing, handshake). Typically $0.5 - 2.0 \; \mu\text{s}$.
  • $\beta$ ($t_w$): Per-word transfer time $= 1 / \text{Bandwidth}$. For 100 GB/s InfiniBand, $\beta \approx 10^{-11}$ s/byte.
  • $L$ ($m$): Message length in words (or bytes).

The Message Packing Lesson:
Suppose you need to send $N$ numbers across the network:
• Sending them as $N$ individual messages costs: $T_1 = N \times \alpha + \beta N$.
• Packing them into 1 single buffer costs: $T_2 = \alpha + \beta N$.
Since $\alpha$ is huge compared to $\beta$, sending individual messages is catastrophically slow! Always aggregate data into contiguous buffers before calling MPI.

9.2 Chapter 15: Foster's PCAM Methodology & Task Dependency DAGs

🔍 Foster's 4-Stage PCAM Design Methodology

  1. P - Partitioning: Decompose the computation and data into the maximum possible number of tiny primitive tasks. (Focus on maximum concurrency; completely ignore target hardware here!). Classify into Domain Decomposition (chopping grid/mesh data) vs Functional Decomposition (chopping algorithmic pipeline stages).
  2. C - Communication: Connect tasks by data-flow dependency links. Classify communication as:
    • Local: Each task talks only to near neighbors (e.g. stencil halo exchanges).
    • Global: Many tasks contribute to a single result (e.g. `MPI_Allreduce` in dot products).
    • Structured vs Unstructured: Predictable grid vs irregular graph.
  3. A - Agglomeration: Group fine-grained primitive tasks into larger composite tasks to:
    • Reduce communication overhead (improve Surface-to-Volume Ratio!).
    • Maintain high cache locality and balance work.
  4. M - Mapping: Assign composite tasks to physical processor cores and nodes. Goals:
    • Load Balancing: Keep all cores equally busy at all times.
    • Locality Maximization: Place heavily communicating tasks on the same physical NUMA socket or node to avoid slow network hops.

💡 Plain-English Intuition: Surface-to-Volume Ratio

Consider a 2D square subgrid of size $L \times L$ assigned to one processor:
• Computation (Volume): Proportional to the area of the domain $= L^2$.
• Communication (Surface): Proportional to the perimeter (boundary cells sent to neighbors) $= 4L$.
• Communication-to-Computation Ratio: $$\frac{\text{Communication}}{\text{Computation}} = \frac{4L}{L^2} = \frac{4}{L}$$ As subgrid size $L$ increases, the communication overhead relative to useful work drops like $1/L$! This is why square subdomains (in 2D) and cubic subdomains (in 3D) are mathematically optimal—they enclose the maximum computation volume with the minimum communication surface area!

10. Parallel Performance & Scalable Linear Algebra (Chapters 16–17)

10.1 Chapter 16: Speedup, Amdahl's Law vs Gustafson's Law & Isoefficiency

💡 Plain-English Intuition: Amdahl vs Gustafson

• Amdahl is Pessimistic (Strong Scaling): You have a fixed workload (e.g. driving 100 miles). 10 miles are through a narrow school zone where you cannot exceed 20 mph ($s = 10\%$). Even if you buy a rocket car that travels at infinite speed for the remaining 90 miles, the 10-mile school zone caps your total speedup at 10x! Adding more processors to a fixed problem yields diminishing returns.
• Gustafson is Optimistic (Weak Scaling): In real supercomputing, when scientists get 1,000x more cores, they don't solve the same tiny problem faster—they simulate the entire global climate at 1-kilometer resolution! As problem size grows with processor count, the parallel work scales up while the serial bottleneck stays tiny. Speedup scales linearly: $S_p \approx p(1-s)$.

🔍 The Scaling Laws Formulated

Scaling Law Scaling Paradigm Speedup Formula Asymptotic Speedup as $p \to \infty$
Amdahl's Law Strong Scaling: Problem size $W$ is fixed. Serial fraction is $s \in [0, 1]$. $$S_p = \frac{1}{s + \frac{1-s}{p}}$$ $$S_{\max} = \frac{1}{s}$$
Gustafson-Barsis' Law Weak Scaling: Workload scales with $p$. Serial fraction on parallel system is $s$. $$S_p = s + p(1-s) = p - s(p-1)$$ $$S_p \to p(1-s) = O(p)$$ (Linear scalability!)

✍️ Exam Hand-Calculation: Deriving the Isoefficiency Function

Problem: Define total overhead $T_o(W, p) = p T_p - W$. Efficiency is $E = \frac{W}{p T_p} = \frac{W}{W + T_o}$. To maintain constant efficiency $E$, what is the required relationship between workload $W$ and processors $p$?

  1. Isolate Workload $W$: $$E = \frac{W}{W + T_o} \implies E(W + T_o) = W \implies E \cdot T_o = W(1 - E)$$ $$W = \left(\frac{E}{1 - E}\right) T_o(W, p) = K \cdot T_o(W, p), \quad \text{where } K = \frac{E}{1-E} \text{ is constant!}$$
  2. Isoefficiency of Parallel Reduction: Adding $n$ numbers on $p$ processors has computation $W = n$. Communication uses a binary tree with overhead $T_o(W, p) = O(p \log p)$. $$\text{Isoefficiency Function: } W = K \cdot p \log_2 p = \Theta(p \log p)$$ Meaning: To keep efficiency at e.g. $80\%$, if you double processor count from $p$ to $2p$, the problem size $n$ only needs to increase by slightly more than $2x$ ($2p \log(2p)$). This algorithm is highly scalable!

⚠️ Deadly Exam Trap: Superlinear Speedup ($S_p > p$)

Can speedup ever exceed $p$ ($S_p > p$, so $E_p > 100\%$)?
YES! In standard theory, $S_p \le p$. But on real physical hardware, superlinear speedup frequently occurs due to cache effects:
When running on 1 processor, the problem size $W$ is too large to fit in cache, causing millions of slow DRAM cache misses. When split across $p$ processors, each processor gets a small chunk $W/p$ that fits entirely inside its private L2/L3 cache! The sudden elimination of DRAM latency makes the parallel code run faster than the theoretical linear rate!

10.2 Chapter 17: Parallel Numerical Linear Algebra & Communication Avoidance

💡 Plain-English Intuition: Cannon's 2D Torus Matrix Multiplication

Naive parallel matrix multiplication requires broadcasting entire rows or columns across all processors (huge communication and buffer memory).
Cannon's insight is pure ballet: Arrange $p$ processors on a $\sqrt{p} \times \sqrt{p}$ torus. First, "preskew" the matrices so the matching sub-blocks line up. Then, in $\sqrt{p}$ choreographed steps: each core multiplies its current local tiles ($C_{\text{loc}} \mathrel{+}= A_{\text{loc}} B_{\text{loc}}$), shifts tile $A$ left by 1, and shifts tile $B$ up by 1. Zero extra buffer memory is required, and communication is reduced from $O(n^2)$ to $O(n^2 / \sqrt{p})$!

🔍 Cannon's Algorithm Step-by-Step

Given sqrt(p) x sqrt(p) processor mesh, each holding (n/sqrt(p)) x (n/sqrt(p)) blocks:

1. Preskewing:
   - For all rows i: circularly shift block A(i, j) left by i positions.
   - For all cols j: circularly shift block B(i, j) up by j positions.

2. Loop k = 0, 1, ..., sqrt(p) - 1:
   - Local Matrix Multiply: C_loc += A_loc * B_loc  [2*(n/sqrt(p))^3 flops]
   - Circularly shift A left by 1 position along row communicator.
   - Circularly shift B up by 1 position along column communicator.

3. Post-alignment (optional): restore original positions of A and B.

Total Communication Cost: 2*sqrt(p)*alpha + 2*beta*(n^2 / sqrt(p)).

⚠️ Deadly Exam Trap: The Parallel Krylov Dot-Product Bottleneck

In parallel Conjugate Gradient (PCG) or GMRES:
• SpMV ($w = Ap$): Involves only local nearest-neighbor halo exchanges between adjacent processors. Communication scales well with $p$.
• Dot Products ($r^T r, p^T A p$): Require a global `MPI_Allreduce` across all $p$ processors! This introduces a $\log_2 p$ latency synchronization barrier. As $p \to 10^5$ cores, processors spend $80\%$ of their time idling at the dot-product barrier!
• Modern Solution: Communication-Avoiding ($s$-step) Krylov & Pipelined CG: Compute $s$ basis vectors at once using matrix powers ($r, Ar, \dots, A^s r$), collapsing $s$ global dot-product synchronizations into a single non-blocking allreduce every $s$ steps!

11. The Ultimate Exam Survival Kit: Master Solver Decision Engine & 25 Deadly Traps

11.1 Master Solver Selection Decision Flowchart

🧭 How to Pick the Winning Solver on Any Exam Problem

Follow this rigorous decision logic whenever you are asked to recommend or analyze a linear solver:

  1. Is the matrix 1D tridiagonal?
    $\implies$ TDMA (Thomas Algorithm). Direct $O(n)$ flops, minimal storage, unconditional speed!
  2. Is the system small and dense ($n \le 5,000$)?
    • If Symmetric Positive Definite (SPD) $\implies$ Cholesky ($A = LL^T$). $\frac{1}{3}n^3$ flops, stable without pivoting.
    • If general non-symmetric $\implies$ LU Factorization with Partial Pivoting ($PA = LU$). $\frac{2}{3}n^3$ flops.
    • If rectangular least squares $\min \|Ax - b\|_2 \implies$ QR via Householder Reflectors. Never use normal equations!
  3. Is the system large, sparse ($n \ge 10^5$), from a 2D/3D PDE?
    (Direct solvers die from fill-in! Iterative solvers required)
    • Is $A$ Symmetric Positive Definite (SPD)?
      $\implies$ Preconditioned Conjugate Gradient (PCG) with Incomplete Cholesky (IC(0)) or SSOR. Minimizes energy error $\|e\|_A$ in $O(\sqrt{\kappa})$ steps!
    • Is $A$ Symmetric INDEFINITE (both positive and negative eigenvalues)?
      $\implies$ MINRES (Minimal Residual) or SYMMLQ. (CG will divide by zero or diverge because $p^T A p$ can be zero!).
    • Is $A$ General Non-Symmetric ($A \ne A^T$)?
      • If you have ample memory and need guaranteed monotonic residual minimization $\implies$ GMRES (or GMRES($m$) with large restart $m$).
      • If memory is strictly bounded ($O(1)$) and system is large $\implies$ BiCGSTAB (smooth, transpose-free, short recurrences).

11.2 The 25 Most Dangerous Exam Traps & Professor Gotchas

These 25 traps represent the most common pitfalls where students lose marks on HPSC exams:

⚠️ 25 Critical Exam Traps

  1. CG on Non-Symmetric Matrices: Never apply Conjugate Gradient to a non-symmetric matrix! It assumes $p_i^T A p_j = p_j^T A p_i$ to collapse the recurrence. If $A \ne A^T$, CG fails catastrophically.
  2. CG on Indefinite Matrices: If $A$ is symmetric but has negative eigenvalues, $p^T A p$ can become zero, causing division by zero in $\alpha_k = \frac{r_k^T r_k}{p_k^T A p_k}$. Use MINRES instead!
  3. Cholesky on Non-SPD Matrices: Cholesky requires taking $\sqrt{l_{ii}}$. If $A$ is not positive definite, you will take the square root of a negative number or divide by zero.
  4. Normal Equations Conditioning: Never compute least squares via $A^T A x = A^T b$. $\kappa(A^T A) = [\kappa(A)]^2$ squares the condition number, destroying precision! Always use QR factorization.
  5. Determinant vs Conditioning: $\det(A) \approx 0$ does NOT mean $A$ is ill-conditioned! (Example: $0.1 \times I_{100}$ has $\det = 10^{-100}$ but $\kappa = 1$). Use singular values $\sigma_{\max}/\sigma_{\min}$.
  6. CGS vs MGS: Classical Gram-Schmidt (CGS) loses orthogonality rapidly in floating point. Modified Gram-Schmidt (MGS) updates the vector immediately after each projection, maintaining numerical orthogonality.
  7. SOR Parameter Bounds: By Kahan's Theorem, $\rho(G_{\text{SOR}}) \ge |\omega - 1|$. Therefore, SOR diverges if $\omega \le 0$ or $\omega \ge 2$. It converges only when $0 < \omega < 2$.
  8. Gauss-Seidel Dependency: Gauss-Seidel is twice as fast as Jacobi, but it CANNOT be naively parallelized across a grid because point $(i, j)$ depends on $(i-1, j)$ and $(i, j-1)$ computed in the same iteration! (Requires Red-Black / Checkerboard ordering to parallelize).
  9. Restarted GMRES($m$) Stagnation: Restarting GMRES every $m$ steps prevents memory blowup, but it can completely stagnate if the residual vector orthogonal to $\mathcal{K}_m$ makes zero progress!
  10. BiCG Breakdown: BiCG can suffer from "serious breakdown" if $r_k^{*T} r_k = 0$ even though $r_k \ne 0$ (division by zero in $\alpha_k$). BiCGSTAB mitigates this.
  11. Left Preconditioning Residual: In left preconditioning $M^{-1}Ax = M^{-1}b$, the residual computed by the solver is $\|M^{-1} r\|$, NOT the true physical residual $\|b - Ax\|$! Right preconditioning $A M^{-1} y = b$ preserves the true residual.
  12. Amdahl's Law Assumption: Amdahl's Law assumes fixed problem size (strong scaling). It does NOT apply when problem size grows with core count (weak scaling, governed by Gustafson's Law).
  13. Superlinear Speedup Cause: If $S_p > p$, it is almost always caused by cache residency (aggregate cache size across $p$ cores fits the working set, eliminating DRAM traffic), not "free extra math".
  14. False Sharing Mechanism: False sharing occurs when two threads on separate cores write to independent variables that sit on the same 64-byte cache line. Hardware MESI coherence invalidates the line back and forth.
  15. Row-Major vs Column-Major Strides: In C/C++, matrices are row-major (`A[i][j]`). The inner loop must iterate over $j$. Inverting the loop (`for j: for i: A[i][j]`) accesses memory with stride $N$, causing a cache miss on every single element!
  16. SpMV Memory-Bound Nature: Sparse Matrix-Vector Multiply (SpMV) has an arithmetic intensity of only $\approx 0.16$ FLOPs/byte ($2 N_{nz}$ flops for $12 N_{nz}$ bytes). It is strictly memory-bandwidth bound on all modern processors!
  17. Dot Product Bottleneck in Parallel Krylov: In parallel CG, SpMV requires only local halo communication, but dot products ($r^T r$) require a global `MPI_Allreduce` across all $p$ cores, creating a $\log_2 p$ synchronization latency bottleneck.
  18. Fill-In in Sparse Direct Solvers: Sparse matrices lose their sparsity during Gaussian elimination. For a 2D $N \times N$ grid, memory grows from $O(n)$ to $O(n^{1.5})$ and flops grow to $O(n^2)$.
  19. Cannon's Preskewing: In Cannon's algorithm, if you forget the initial preskewing (row $i$ shifted left by $i$, col $j$ shifted up by $j$), the multiply-and-roll sequence will compute completely incorrect dot products!
  20. Foster's Agglomeration Goal: Agglomeration groups fine-grained tasks to increase the Surface-to-Volume ratio ($\frac{\text{Computation}}{\text{Communication}} \propto L$), reducing communication overhead relative to computation.
  21. Isoefficiency Meaning: If an algorithm has isoefficiency $W = \Theta(p)$, it is optimally scalable (doubling processors only requires doubling workload to keep efficiency constant). If $W = \Theta(p^3)$, it scales very poorly.
  22. Network Latency vs Bandwidth: In $T = \alpha + \beta L$, for small messages ($L \ll \alpha/\beta$), latency $\alpha$ dominates; for large messages ($L \gg \alpha/\beta$), bandwidth $\beta$ dominates.
  23. Spectral Radius vs Matrix Norm: $\rho(A) \le \|A\|$ for any induced matrix norm. $\rho(A)$ is NOT a norm itself (it violates triangle inequality for general matrices!). However, for symmetric $A$, $\rho(A) = \|A\|_2$.
  24. Strict Diagonal Dominance: If $|a_{ii}| > \sum_{j \ne i} |a_{ij}|$ for all $i$, both Jacobi and Gauss-Seidel are guaranteed to converge, regardless of initial guess!
  25. Lanczos Loss of Orthogonality: In finite precision arithmetic, Lanczos loses orthogonality as soon as an extremal Ritz value converges to an eigenvalue, creating spurious "ghost eigenvalues" in $T_m$!

Ch 13: Architecture & Caches

Key Formula: Tiled matrix multiply misses $= O(n^3/b)$. Cache line $= 64$ bytes.

Concept: 3 C's of misses: Compulsory, Capacity, Conflict. Row-major (C) requires row-by-row traversal.

Trap: False sharing: independent thread variables sharing one 64-byte line cause continuous MESI invalidation ping-pong!

Ch 14: Flynn & Interconnects

Key Formula: Hockney latency: $T = \alpha + \beta L$. Hypercube: $d=\log_2 p, D=\log_2 p, B_w = p/2$.

Concept: Flynn: SISD, SIMD, MISD, MIMD. Shared memory: UMA vs NUMA. Fat-Tree provides non-blocking full bisection bandwidth.

Trap: Sending many small messages wastes time on latency $\alpha$; always aggregate/pack messages before sending!

Ch 15: Foster's PCAM Design

Key Formula: Surface-to-Volume ratio: $\frac{\text{Comm}}{\text{Comp}} = \frac{4L}{L^2} = \frac{4}{L} \to 0$ as $L \to \infty$.

Concept: 4 stages: Partitioning (max concurrency), Communication, Agglomeration (surface-to-volume ratio), Mapping (load balancing).

Trap: DAG critical path $T_\infty$ sets the absolute minimum execution time even on infinite processors!

Ch 16: Scalability & Amdahl

Key Formula: Amdahl: $S_p = \frac{1}{s + \frac{1-s}{p}} \le \frac{1}{s}$; Gustafson: $S_p = s + p(1-s)$.

Concept: Overhead $T_o = p T_p - W$. Isoefficiency: $W = K \cdot T_o(W, p)$ maintaining constant efficiency $E$.

Trap: Superlinear speedup ($S_p > p$) is real—caused by aggregate processor caches eliminating DRAM misses!

Ch 17: Parallel Linear Algebra

Key Formula: Cannon's Matrix Multiply: Preskewing + $\sqrt{p}$ steps of local multiply-accumulate and 1-position shifts.

Concept: 2D block SpMV reduces communication from $O(n)$ to $O(n/\sqrt{p})$. Communication-avoiding Krylov collapses dot product allreduces.

Trap: In parallel Krylov solvers, dot products (global `Allreduce`) create a severe $\log_2 p$ synchronization barrier at large scale!

Ch 18: Exam Synthesis

Key Formula: Master decision tree: Tridiagonal $\to$ TDMA; Small SPD $\to$ Cholesky; Large SPD $\to$ PCG; Non-symmetric $\to$ BiCGSTAB / GMRES.

Concept: Always identify matrix properties first: size, sparsity, symmetry, positive definiteness, condition number.

Trap: Never jump to an advanced iterative solver when an exact $O(n)$ direct solver (like TDMA) applies!
